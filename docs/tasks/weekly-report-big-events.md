# 周报 + 大事件触发（2026-10-16）

用户已确认：周报（周日晚上）+ 大事件触发（有大事件就单独发，不等日报）。
只报重点：主线 + AI 选的 + 风险 + 涨停龙头，其他票不报。
不编数据，缺就是缺（写“没取到”）。

## 一、周报内容（`GET /api/weekly-report`，`POST /api/weekly-report` 手动生成）

本周总结（本周一～周日，有板块快照的交易日）：

- 大盘：上证指数本周涨/跌（日 K 首收 → 末收；日 K 里没有指数行 → “没取到”）
- 全市场中位个股本周涨/跌（板块快照各日中位涨跌复利）
- 最强 / 最弱板块（前 3 / 后 3，按本周复利涨跌排）
- 本周主线（本周涨 > 0 的板块前 3）+ 主线变化（续留 / 新进 / 掉出，对比上周）
- 战绩：本周 AI 优选计入战绩几天、已回填几天、平均次日净收益（扣费后，等权）、上涨只数、跑赢/跑输全 A 中位基准；未回填 → “没取到”
- 涨停龙头：本周连板 ≥ 3 的票（涨停名单沉淀）
- 风险：本周全周减持汇总“没取到”（巨潮公告只在日报里按日汇总，不编一周总数）；主线连续减持看本周各日报的主线减持一节

下周看什么：

- 下周交易日（真实交易日历，带星期）+ 下周休市段（连续 ≥ 2 天）
- 下周美联储议息：已知会议日期落在下周内才提醒（“10月28日”可解析，“12月”无具体日 → 无法判断）
- 财报：没取到（暂无财报日历数据源，不编）
- 解禁：没取到（暂无解禁日历数据源，不编）
- 下周重点看本周主线能不能续上；主线断了先别追

实现：`src/lib/desk/weekly-report-core.ts`（纯核）+ `src/lib/desk/weekly-report.ts`（IO：板块快照归档 + 上证日 K + AI 优选战绩 + 涨停名单 + 预测市场 + 交易日历）。
归档：`data/weekly-reports/<本周日>.json`。每次执行写 `task_run`（kind=weekly）。

## 二、周报定时

- 周日北京时间 20:00，调度器 tick 里独立判定（`isWeeklyDue`），不走收盘后窗口（周日本来就不开盘），不走交易日确证（总结的是过去一周）。
- 幂等：同一（weekly，本周日）已有 success → 跳过；30 分钟内的 running → 跳过；`force=true` 才重跑。
- 边界与收盘后调度器一致：任务随服务端进程运行，服务没启动就不会跑；每次执行都写 `task_run`。
- 手动补跑：`POST /api/weekly-report { week?, force?}`。

## 三、大事件触发（单独发，不等日报）

检查：工作日 9:30–15:30，每 15 分钟一次（`isBigEventDue` 节流，不是每 tick 都查）。

触发条件（任一命中即一条提醒；日常波动不触发）：

| 触发 | 阈值 |
|---|---|
| 美联储议息 | 快讯级别 = 全球级事件 + 标题含美联储 / FOMC / 议息 / 鲍威尔 |
| 重磅政策 | 快讯级别 = 全球级事件 / 重大产业事件 + 标题含降准 / 降息 / 证监会 / 国务院 / 发改委 / 政治局 / 国常会 / 央行 / 印花税 / 减税 / 刺激等 |
| 板块突然暴涨 / 暴跌 | 当日板块涨跌幅绝对值 ≥ 5%（同花顺行业榜，盘中实时） |
| 某只票突然涨停 / 跌停 | 只报重点：主线板块龙头或 AI 选的票，领涨股涨跌幅 ≥ 9.5% / ≤ -9.5%；非重点票 20cm 真封板（≥ 19.5%）也报；日常首板不报 |
| 大盘暴涨 / 暴跌 | 上证指数当日涨跌幅绝对值 ≥ 3%（只在收盘后有当日涨跌幅时判定，盘中取不到就不判） |

触发时发什么（一短条提醒，固定四段）：事件是什么、方向（利多 / 利空 / 双向）、影响、重点看什么。
例如板块暴涨：`半导体今天涨 6.2%（≥5%）。方向：利多该板块。影响：资金在往这个板块涌，主线可能正在往这儿切。重点看：龙头 XX 能不能封住、板块资金是真流入还是拉高出货，别追高。`

去重：`dedupeKey = 日期:种类:主体`，同日同类同主体只发一次；去重在提醒级别，任务本身可重复跑。
归档：新增提醒追加到 `data/big-event-alerts.json`；有新增时写 `task_run`（kind=bigevent），零新增不写空行（调度器 lastOutcome 里仍有“已检查、无新增”）。
手动检查：`GET /api/big-events`（只判定不落档）/ `POST /api/big-events`（判定 + 去重 + 归档）。

## 四、发送说明

本层只生成 + 归档 + 记账，不直接发给用户。发送走日报同款发送通道（调用方取归档/接口结果发出）。
周报与大事件提醒的发送由调用方负责；`task_run` + 归档文件是“有没有生成、什么时候生成”的唯一依据。
