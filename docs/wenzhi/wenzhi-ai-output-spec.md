## 1. 输出管线（任务式，不是裸 SSE）

```
POST /api/ai-agent/tasks            → 建任务，拿 task_id
GET  /api/ai-agent/stream/{taskId}?last_event_id=N   ← EventSource（withCredentials）
```
- `last_event_id` 断线续传：重连时带上最后收到的事件序号，服务端按序补发（前端 `zr()` 拼 URL、`qn(taskId,{lastEventId})`）。
- 拿到 `done` 后前端 `loadHistory()` + `openSession(session_id,{source:"done"})` 回读落库版本——**流式只是过程，最终以服务端落库的 `canonical_markdown` 为准**。
- 连接异常有四级降级文案：`连接已降级为轮询` / `实时进度已切换为后台同步` / `正在补齐实时进度，已同步任务快照` / `检测到异常信号，正在核对任务状态`——全部带 `request_id`。

事件名（前端监听列表）：`stage`、`answer_chunk`、`agent_started`、`answer_started`、`answer_finished`，以及 step / warning / done。

## 4. 六阶段 Agent Loop（与本仓 `AGENT_PHASES` 逐字一致）

每个 step 的真实字段：`phase_key`、`step_kind`（`tool_call` / 非）、`parent_step_id`、`sort_index`、`duration_ms`、`tool_name`、`status`。

| `phase_key` | 进度标题（进行时） | 折叠条标题（完成态） |
|---|---|---|
| `intent` | 正在理解问题 | 理解问题 |
| `skills` | 正在选择分析方法 | 选择分析方法 |
| `local_data` | 正在获取行情与市场数据 | 获取行情与市场数据 |
| `external_data` | 正在核查公开信息 | 核查新闻与公开信息 |
| `research` | 正在综合分析 | 综合分析 |
| `answer` | 正在输出分析结论 | 生成结论 |

状态映射：`done/completed/ready/success/finished`→已完成 ✓；`active/running/loading/in_progress/streaming`→进行中 ●；`error/failed`→失败 ⚠；其余→等待中 ○。
**同一步骤去重规则**：key = `phase_key|parent_step_id|"tool"` + 归一化后的 label（去掉 `正在|已完成|已核对|获取|查询` 前缀与 `：:·•空白`），重复时取「状态权重更高」的那条（done1 < pending2 < active3 < error4），耗时取 max。

## 5. 答案正文的三个字段与 5 个状态

```
canonical_markdown  落库后的最终答案（权威）
answer_content      同义字段
streaming_markdown  流式中间态（只用于过程展示）
answer_state        idle | answer_streaming | finished | degraded | incomplete | failed
```
- `D(t)` 取值规则：状态是 `answer_streaming|finished` 时**优先用 `streaming_markdown`**，否则 `canonical_markdown || answer_content`。
- 只有 `finished / degraded / incomplete / failed` 或已有正文，才算「结论已形成」（`hasResolvedAnswer`）。
- **思考占位不算正文**：`🧠 深度思考中…` / `⚡ 快速分析中…` 被显式识别并从「是否有输出」判定里剔除。

## 6. 正文的 Markdown 渲染契约（这才是"稳智的回答长什么样"）

渲染器是 markdown-it（`linkify:true, breaks:true, html:false`）+ 一串自定义规则：

1. **自动给标题加 emoji**（模型不写 emoji，前端按关键词补第一个）：
   | 命中关键词 | 补的图标 |
   |---|---|
   | 风险/止损/失效/防守 | ⚠️ |
   | 仓位/减仓/操作/计划/买点/卖点 | 🧭 |
   | 资金/主力/量能 | 💰 |
   | 技术/趋势/均线/支撑/压力/回踩 | 📈 |
   | 新闻/消息/公告 | 📰 |
   | 市场/板块/轮动/情绪 | 🔥 |
   | 财报/业绩/基本面/估值/数据/证据 | 📊 |
   | 结论/判断/总结 | 🎯 |
   | （其它标题） | 📊（h1 时） |
2. **首段无标题且不带 emoji → 升格为"重点块"（hero）**：h1 走 `emphasis=hero`，h2 走 `section=key`。
3. **`**短标签**：`（≤42 字、必须以半角/全角冒号结尾、且冒号外面没空格）**被专门解析**为"键值标签"（`spaced_short_label_bold` 规则）——所以稳智的正文是**大量 `**加粗短标签**：内容` 的清单体**，而不是长段落。
4. **引用块（`>`）= 决策块**：`data-ai-tone` 继承当前 tone，非 neutral 时改为 `decision`。
5. **表格**：包一层 `.ai-table-scroll`，`role="region"`、可横向滚动、`tabindex=0`。
6. **免责声明单列**：含 `免责声明 / 仅供参考 / 不构成投资建议` 的段落标成 `note`，并从"重点块"判定里排除；`presentation_meta.disclaimer` 单独给一个 emphasis。
7. **每个块被归到一种 tone**（`data-ai-tone`），正则顺序即优先级：
   ```
   risk       风险|止损|失效|防守|警惕|注意
   action     仓位|减仓|加仓|操作|计划|买点|卖点|策略|执行
   capital    资金|主力|量能|成交|筹码
   technical  技术|趋势|均线|支撑|压力|回踩|形态|指标
   fundamental财报|业绩|基本面|估值|盈利|公司|产业|行业逻辑
   market     市场|大盘|板块|轮动|情绪|环境
   event      新闻|消息|公告|催化|事件
   decision   结论|判断|总结|定性|一句话
   note       免责声明|仅供参考|数据基准|数据口径|边界
   neutral    （都没有）
   ```
   → 反过来说明：**稳智的答案必须让每个小节都能被这些词命中**，否则拿不到对应的视觉样式。
8. **后端可下发 `presentation_meta`**：`{ emphasis:{level,section,body,disclaimer}, divider:{}, dividers:[], sections:[] }` —— 结构化控制哪段是重点、在哪插分割线。
9. 预处理会做**规范化**：`\r\n`→`\n`、`\u00a0`→空格、连续 3+ 空行压成 2 行、连续水平线 `---` 去重、奇数个 ``` 自动补闭合。**这意味着稳智容错但不"美化"内容**。

## 8. 选股/筛选类答案的**硬契约**（会被前端正则解析，写错就少一块 UI）

前端从最后一条 assistant 正文里按**行首小节名**切块：

```
核心判断          → judgement
板块/概念焦点     → themes
最终关注清单      → watchlist
```

- 列表项格式：`- xxx` 或 `1. xxx`（`^[-*•]\s+` 或 `^\d+\.\s+`）。
- **自选清单每行的格式被严格要求**：`名称 (代码) | 标签 | 标签`
  → 正则 `^(.+?)\s*\(([^()]+)\)(?:\s*\|\s*(.+))?$`，解析成 `{name, symbol, tags[], actionText:"分析{名称}能不能买"}`，最多取 8 条。
- 触发条件（`En()`）：正文包含 `已调取昨日 run 报告` 或 `最终关注清单`，**或** `data_debug.loaded_blocks` 含 `run_report_context` / `theme_heat_all_in_one`。
- 解析出来之后自动生成追问按钮：`分析最终关注清单里哪些股票值得优先关注，并按股票分别给结论` / `分析{股票}能不能买` / `分析{方向}这个方向还能不能做` / `分析最终关注清单里哪些适合低吸`。

> 落地含义：**这是一份机器可读的输出契约**。模型少写一个「最终关注清单」标题，整块清单 UI 就没了。

## 10. 进度条与"流动感"的叙述口吻

`flowVisualRegistry` 的 hero 主文案（按优先级）：
```
已有结论     → ✅ 盘中结论已生成
有活跃工具   → 正在执行工具：{工具名}
有活跃步骤   → 正在进行：{步骤名}
有最近完成   → ✅ 最近完成：{步骤名}（进度=100% 时改成 ✅ 本轮研究已完成）
都没有       → 🔬 正在整理研究进度
```
副标题（计数摘要）：`{N} 个工具步骤 · {N} 条 loop 摘要 · {N} 条提示 · {N} 条命中诊断`
chips：`已运行 {X}` / `最近更新 {Y} 前`
折叠条标题：`✨ AI 正在分析` / `✨ AI 已完成分析`，摘要 `已完成 {N} 步`

**细节**：live detail 只有在**以 `正在|已核对|已获取|已整理|准备|继续` 开头、长度 ≤42 字、且不含 URL/`[]{}<>`** 时才展示——超过 12 秒没有新进展就降级成 `正在等待：{当前步骤}`。这是在明说：**"正在…"的短句才配出现在进度条上**，长话和链接不许往里塞。

## 11. 语气规范（从输入模板库反推 —— 这是最有价值的一节）

稳智的"提问模板"同时也是**对输出的要求**。逐条摘出对回答口吻的硬要求：

| # | 原文要求 | 落到输出上 |
|---|---|---|
| 1 | 先给判断，再说依据、值得观察的方向和判断失效的信号，**注明数据时间** | 结论前置；末尾必须挂数据时点 |
| 2 | …说明参与条件和**退潮信号**，**不预设低吸有效** | 不许把"回踩=机会"当默认前提 |
| 3 | **不要以回本作为判断依据**；仓位未知时请说明 | 持仓纪律不锚定成本价；缺信息就明说 |
| 4 | 没有合适机会就**直接说明**；没有足够证据或没有合格方向时直接说明，**不凑数量** | 明确允许"不做"，允许少于 N 个结果 |
| 5 | 最后**明确现在适合参与、等待还是回避** | 三选一，不给模糊态 |
| 6 | 给入场条件、仓位建议、失效条件和主要风险 | 固定四件套 |
| 7 | 每一维都要列出关键数据、证据和结论，**进行多源交叉验证**；本地没有的数据**直接实时搜索**，盘中**必须加载实时行情** | 数据可溯源 + 缺数要补取，不许拿推断顶 |
| 8 | 给出**可执行的**操作计划 / 触发条件 / 仓位口径 | 给动作，不给"仅供参考"式客套 |
| 9 | 做 T 需考虑**已有底仓与当日可卖数量** | 落地时考虑现实约束 |
| 10 | 区分**盘中短暂跌破与收盘确认** | 同一现象分时态给不同结论 |
