## 三、做得不好的（3 项）

### 1. ❌ P0 #2 Markdown emoji 卡片化（部分完成）

**原始差距**：稳智的前端 Markdown 渲染器识别 emoji 前缀（`- 📌 xxx：yyy`）渲染成独立卡片（LineageCard 变体）。

**现状**：
- P21 结论契约做了 4 类固定前缀（🎯/🧭/🔍/🛑）的强识别 → 卡片渲染
- 但通用的 9 类 emoji 卡片（📊 资金面 / 📈 技术面 / 📌 备注 等）还没有做完整的 Markdown 识别 → 卡片化
- 稳智是「前端识别 emoji 前缀 → 自动卡片化」，本仓库是「后端约定固定前缀 → 前端识别」

**差距**：
- 稳智的卡片化是**前端自动识别**（任何 emoji 前缀都能识别成卡片）
- 本仓库是**后端约定 + 前端识别**（只有约定好的前缀才能识别成卡片）
- 如果模型输出格式不遵循约定（比如用了不同的 emoji），前端识别不到

**建议**：P4 可选。改进 Markdown.tsx，让前端自动识别任意 emoji 前缀的 bullet 渲染成卡片。但工作量中等（需要解析 bullet + 提取 emoji + 匹配卡片类型），且当前 4 类固定前缀已经覆盖了核心场景。

### 2. ⚠️ SSE 事件流不完整（缺 3 种事件）

**原始差距**：稳智有 14 种 SSE 事件（stage/step/agent_started/answer_started/answer_chunk/answer_finished/ping/block_started/block_finished/channel），本仓库只有 8 种。

**现状**：
- ✅ stage 事件（P24）
- ✅ block_started/finished 事件（P26）
- ❌ agent_started 事件（未做）
- ❌ answer_started/finished 事件（未做）
- ❌ ping 心跳（未做）
- ❌ channel 通道（未做）

**差距**：
- 缺 agent_started：子 Agent 起跑时前端无法显示「子 Agent 正在分析」提示
- 缺 answer_started/finished：回答包裹事件，前端无法精确判断回答开始/结束
- 缺 ping 心跳：SSE 连接没有保活，长时间流式可能断连
- 缺 channel 通道：稳智有 flow/reasoning/answer 三条通道，本仓库只有单条流

**建议**：P3 可选。ping 心跳最值得做（SSE 保活，15 秒一次），工作量小（后端 setInterval + 前端忽略 ping 事件）。agent_started 和 answer_started/finished 依赖后端 Agent Loop 编排，工作量中等。channel 通道是架构级改动，不建议做。

### 3. ⚠️ 交易周期跨会话记忆（未做）

**原始差距**：稳智的 `activeCandidateTradingHorizon` 跨会话记忆（周期绑定到候选股票，跨会话持久化）。

**现状**：
- P28 做了 5 档交易周期 + 自动检测（resolveTradingHorizonForInput）
- 但周期只存在 store（zustand persist 到 localStorage），没有跨会话记忆
- 用户每次新开会话都要重新选周期

**差距**：
- 稳智：周期绑定到候选股票，跨会话记忆
- 本仓库：周期只在当前 store 里，新会话清空

**建议**：P3 可选。把周期存到 session.stock 里（和 focusSymbol 一起），新会话继承。但工作量小（0.5 天），且当前用户手动选的周期已经够用。

## 五、本仓库比稳智做得好的（5 项）

### 1. ✅ 测试覆盖率（稳智无公开测试）

稳智是生产环境前端 bundle，没有公开测试。本仓库每个 P 阶段都有独立测试文件，全量 1310 tests。稳智的测试质量未知，但本仓库的测试覆盖率明确且可验证。

### 2. ✅ 双引擎意图识别（稳智是硬编码模板）

稳智是「12 模板 × 5 周期 = 60 种组合」，按意图选 1 个模板。本仓库是「双引擎（规则 + LLM）+ 11 字段决策信号 + 4 类结论契约」。本仓库的意图识别更灵活（LLM 可以处理模糊输入），稳智的模板路由更精确（硬编码但稳定）。

### 3. ✅ 向后兼容（稳智无兼容层）

本仓库每个 P 阶段都考虑了向后兼容：
- images 字段可选（没图时请求体逐字节一致）
- phase_key 可选（fallback 到语义映射）
- parentStepId 可选（fallback 到扁平步骤）
- runRef.createdAt 可选（过期检查向后兼容）

稳智没有向后兼容层（生产环境直接改），本仓库有明确的兼容策略。

### 4. ✅ 错误处理更精细（稳智是兜底式）

稳智有 8 条错误码 → 用户文案映射，本仓库有 11 个错误码 + friendlyErrorMessage 纯函数 + normalizeCode 归一化。本仓库的错误码更多、映射更精细、归一化更稳健。

### 5. ✅ 任务过期机制（稳智有 15 分钟但本仓库更精确）

稳智的任务过期时间是 15 分钟（从 task_id 生成时间算）。本仓库的 runRef.createdAt 是精确的毫秒时间戳，过期检查更精确（`ref?.createdAt == null` 向后兼容 + `isRunRefExpired(ref, now)` 纯函数）。
