### 1.2 P33 的设计（合规，值得保留）

- **概率分工红线**：概率只来自概率引擎与使用台账；AI 优选不产出概率；市场级概率是全市场一个数，单独一行，**绝不复制到单条头上**。
- `packForecast` 里 `record` 恒 `null`（v1 无台账，不编数）；`marketProbState` 恒 `accumulating`，攒够也只说「样本已攒够」，**不拿无条件 base rate 冒充条件概率**。
- 档位分 `null` → `unknown` 不猜（「没判」≠「被挡」）。

**结论：Zcode 绕开了禁区而非破坏它**——输出的是「今天哪些策略的前提成立」（技术条件匹配），不是「上涨概率」。禁区代码（`event-interpret-core.ts` 的 `stripProbabilityClaims`）原样未动。

## 二、诊断：预测按钮在非高风险日「恒空」

### 2.1 根因

- 策略库 468 条中 **99 条带 `sentiment_threshold`**，阈值分布 `[50, 60, 75, 80, 90]`，**最低 50**。
- 档位分是 0–100 见顶压力分，**市场越正常分越低**。今天 28.2 分（正常档）→ 99 条**全部低于最低门槛**，无一过闸 → `items=0`。
- 即：**除非市场进入「偏高/高风险」（≥50），用户点「预测」永远看到空态文案。**

### 2.2 更深层的问题：闸门阈值是拍脑袋的，回测数据是真实的

Zcode 今晨 07:01 已跑出全量分档回测（全A 5369 只 × ~300 交易日，上证 MA20 趋势分档：强势 192 / 震荡 97 / 弱势 86 天），落在 `data/_probe-strategy-regime.json`（566KB，**被 .gitignore 排除**）。其结论直接打脸那些 threshold：

- **「放大量」（涨停+MACD金叉）三档全第一**，且**弱势期反而最强**：强 62%/+2.33%、震 63%/+2.31%、**弱 69%/+2.86%（5日 +4.76%）**。
- 回测证明很多策略在各档都能用，却被 `≥50` 的门槛挡在门外——**门槛与真实表现脱节**。

## 四、方案（分阶段）

### P34-1 分档回测产品化（地基，1 步）
- 把一次性脚本落成可复跑：`scripts/strategy-regime-backtest.mjs`（以 `dedupe_strategies.mjs` 为模板）。
- 大盘档位判定（上证 MA20 趋势法）抽成**纯核** `regime-core.ts`，回测与线上共用同一判据，避免两套口径。
- 产出改落 `data/strategy-regime.json`，**进 git**（不再用被 ignore 的 `_probe-` 前缀）。

### P34-2 推荐来源改回测排名（治恒空，核心）
- 弹卡新增**分档推荐**通道：取今天大盘档位（强/震/弱）→ 该档回测排名前 N（建议 Top 5，弹卡不摆 15 条）。
- **理由行只写真实回测数字**，格式：
  `该档命中 685 次 · 次日胜率 62% · 次日均益 +2.33%（全期 1357 次）`
- **样本门槛沿用**回测口径：该档命中 ≥20 次且全期 ≥30 次，不足不上榜（沿用 `情绪分类策略选择.txt` 已定的门槛）。
- 原 threshold 闸门**保留但不作为唯一判据**，改为双通道标注：
  - 过闸 → 标「能用」；
  - 回测上榜 → 标「回测推荐（该档第 N）」。
  这样正常档也有推荐，且每条都带真实胜率/均益，比「赞/踩」排序硬。

### P34-3 接 15:20 定时重算
- 分档回测随收盘重算（全量 5369×300 耗时长，建议**每周一次全量 + 每日增量**）。
- 若接调度，需给 `TaskKind` 加一个 kind（现为 7 个：radar/events/breadth/review/roster/sectorsnap/dailysnap）。

### P34-4 口径与红线（不可省）
- 理由行写「历史统计」，**必须带 N 与口径**；胜率是频次（62% 的日子收涨）≠ 概率（概率要有 CI）。
- **不写「上涨概率」字样**——除非走完 P1+P2 放行流程。
- 保留既有红线：市场级概率单独一行，不复制到单条；`record` 无台账前恒 null。

### P1 Wilson 置信区间（可与 P34 并行，纯计算）
